## Purpose

Defines the repository-generic collection, analysis, candidate-functional-set, and approved-functional-set process governing the pre-decomposition lifecycle.

## Normative requirements

- `REPO-FSP-001`: Functional-set, product-decomposition, and implementation-plan development documents shall use the canonical roots and type mapping defined by repo.development-document-base; this specification owns only functional-set-specific semantics.
- `REPO-FSP-002`: An overview whiteboard shall durably record unordered user statements, discovered evidence, provenance, and unresolved intent before interpretation. Collection shall not prematurely convert that material into requirements, decomposition, specifications, implementation plans, implementation, or functional-set approval.
- `REPO-FSP-003`: An overview analysis shall consume recorded whiteboard evidence and identify capability-oriented groupings, dependencies, ambiguities, candidate functional-set boundaries, and candidate FS0/core choices without itself establishing approved product direction.
- `REPO-FSP-004`: A functional set shall be capability-oriented rather than a technical-layer slice, shall define a bounded directional unit suitable for downstream decomposition, and shall remain non-normative with respect to exact product behavior, interfaces, schemas, implementation architecture, and release readiness.
- `REPO-FSP-005`: Approval of a functional-set document establishes the directional authority handoff into decomposition work; it does not by itself authorize an implementation plan or implementation mutation outside the downstream governing contracts.
- `REPO-FSP-006`: Whiteboard evidence shall persist beyond functional-set approval so deferred or unaccepted intent remains available for successor analysis. Analysis and functional-set documents shall preserve predecessor and evidence traceability rather than silently absorbing unresolved intent.
- `REPO-FSP-007`: The overview process shall support multiple candidate functional sets, including candidate FS0/core choices, before approval. An approved functional set shall explicitly declare decomposition handoff readiness.
