## Normative requirements

- `INIT-L3-001`: The full initialization workflow shall compose the request intake, source material resolver, destination preflight, staging manager, framework installation, foundation seeding, execution orchestrator, repository validation, and provenance and handoff components into a single end-to-end orchestration that produces a validated, provenance-tracked initialized repository at the declared destination.
- `INIT-L3-002`: The full initialization workflow shall execute the lifecycle stages in order: request intake, source resolution, destination preflight, staging workspace creation, framework installation, foundation seeding, repository validation, provenance recording, handoff assembly, and destination promotion.
- `INIT-L3-003`: The full initialization workflow shall halt and report failure when any required component produces an error, and shall not promote staging content to the destination when validation fails.
- `INIT-L3-004`: The dry-run validation workflow shall compose the request intake, source material resolver, destination preflight, and repository validation components to validate that an initialization request is structurally valid, the source revision is resolvable, the destination is compatible, and the expected generated content would pass validation, without creating a staging workspace or modifying the destination.
- `INIT-L3-005`: The dry-run validation workflow shall produce a validation report indicating whether the initialization request would succeed, and shall report the exact reasons for any predicted failure without partial destination mutation.
- `INIT-L3-006`: The resume-from-staging workflow shall compose the staging manager, repository validation, and provenance and handoff components to recover and complete an initialization from a previously preserved staging workspace, without re-executing request intake, source resolution, or framework installation.
- `INIT-L3-007`: The resume-from-staging workflow shall verify that the preserved staging workspace is internally consistent and compatible with the original initialization request before proceeding with validation and promotion.
- `INIT-L3-008`: The platform-integrated initialization workflow shall compose the full initialization workflow with the platform profile executor, applying the selected platform profile's repository establishment operations after staging promotion and before the final provenance and handoff assembly.
- `INIT-L3-009`: The platform-integrated initialization workflow shall treat platform profile execution as a distinct post-promotion stage whose failure does not roll back the promoted repository content but shall be recorded in the execution report.
- `INIT-L3-010`: The recovery and cleanup workflow shall compose the staging manager, execution orchestrator, and provenance and handoff components to handle initialization failures, clean up staging workspaces, and produce a failure report that identifies the failing component, the error reason, and any preserved diagnostic state.
- `INIT-L3-011`: The recovery and cleanup workflow shall not silently discard diagnostic state: when a staging workspace exists at the time of failure, the workflow shall either preserve it for inspection or explicitly report its cleanup with a record of the disposed content.
- `INIT-L3-012`: The initializer shall accept an initialization request, select one of the supported workflows based on the execution profile and request parameters, and dispatch to the corresponding orchestration.
- `INIT-L3-013`: The initializer shall reject a request that selects an unsupported workflow combination and shall report the reason for rejection without performing partial initialization.
- `INIT-L3-014`: The initializer shall produce a deterministic output for equivalent initialization requests, source revisions, and execution profiles: the same input triple shall produce the same initialized repository content and the same handoff manifest, except for explicitly declared variable data in the provenance record.
- `INIT-L3-015`: The initializer shall record the completed workflow identity, the composition of components used, and the version of each component in the execution report for diagnostic and provenance purposes.
