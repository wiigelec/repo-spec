## Normative requirements

- `UPG-TFA-001`: For each accepted framework reconciliation lineage revision governed by this contract, the initialized repository shall maintain a deterministic repository-local framework-authority bundle at `repo/initializer/framework-authority/<framework-sha1>/`, where `<framework-sha1>` is the exact lowercase SHA-1 object ID of that accepted framework commit.
- `UPG-TFA-002`: A framework-authority bundle shall retain the exact Git commit object identified by the corresponding accepted lineage revision and the minimal tree/blob object closure necessary to resolve the authoritative initialization inventory endpoints and framework source objects required to prove initializer-managed `repo/` material for that revision.
- `UPG-TFA-003`: Every retained Git object shall be locally verifiable by recomputing its canonical Git object identity from object type, byte length, and uncompressed content; the bundle shall fail validation when any retained object's computed identity differs from its stored object ID.
- `UPG-TFA-004`: Framework-authority verification shall begin from the exact accepted lineage commit object ID and traverse only cryptographically linked Git tree/blob identities to resolve required inventory and source content; a repository-local index, manifest, path list, digest list, or other sidecar metadata shall be subordinate evidence and shall not independently authorize managed content.
- `UPG-TFA-005`: The retained object closure shall be sufficient to determine the initializer-managed `repo/` destination authority relevant to the accepted state, including authoritative inventory identity, stable managed-material correspondence, exact source blob bytes, executable/non-executable mode where governed, and historical managed paths needed to distinguish authorized transition from unrelated committed repository drift.
- `UPG-TFA-006`: The bundle representation and any subordinate index shall be deterministically serialized/stored so equivalent accepted framework identity and authoritative inventory/source content produce equivalent repository-local authority content.
- `UPG-TFA-007`: Routine validation of a promoted initialized repository shall be able to verify framework-managed repository integrity using only the promoted repository's committed lineage and framework-authority bundles; it shall not require the originating local repo-spec checkout and shall not retrieve framework authority from a network or remote repository.
- `UPG-TFA-008`: Missing, malformed, incomplete, internally inconsistent, unanchored, or tampered framework-authority evidence required for the accepted lineage state shall fail closed; coordinated modification of managed content and subordinate local metadata shall not be sufficient to produce a valid authority proof.
- `UPG-TFA-009`: When an initialized repository has accepted lineage entries that predate this framework-authority representation, a later governed upgrade may materialize the missing historical bundles only from the exact locally resolvable framework repository/revision identities already recorded by accepted lineage or valid legacy provenance; unresolved history shall not be guessed and remote retrieval is not authorized.
- `UPG-TFA-010`: A prospective reconciliation-target framework-authority bundle, together with any required exact historical backfill, shall be present in the staged candidate before complete staged validation; non-promoted attempts shall not advance accepted lineage or accepted framework-authority state.
