## Normative requirements

- `INIT-RVA-001`: The repository validation component shall execute two validation phases in order: Phase 1 (input and source) validates request schema, canonicalization, authority propagation, source repository, source commit, material-manifest schema, source paths (rejecting tree-valued entries), and key coverage. Phase 2 (staged repository and Git state) validates the complete staged repository at repository/ including output inventory (confirming no tree-valued material_index entries), copied files, direction evidence, generated templates, promoted records, provenance, handoff, content digest, Git branch, commit count, author identity, commit message, worktree cleanliness, and remote count. Staging-state record validation is not an ordinary Phase 1 or Phase 2 check; it is performed during report finalization.
- `INIT-RVA-002`: Each phase shall execute checks in ascending order number within that phase, using the checks declared in the validation profile (product.validation-profile) for the corresponding applies_to scope, and shall produce a validation report conforming to the validation report specification (product.validation-report) with status values passed, failed, error, or skipped, stable failure codes from each check's declared failure_codes array, and structured evidence fields.
- `INIT-RVA-003`: After all Phase 1 and Phase 2 checks are recorded, the validation component shall perform report finalization: validate the staging-state record against the product.staging-state schema (including request_fingerprint, repository_content_digest, validation_completed, and validation_overall_status agreement), verify request_fingerprint linkage between the report and the staging-state record, verify repository_content_digest linkage, verify check ordering and uniqueness, calculate overall_status, validate the completed report schema, and serialize the final report. Promotion is permitted only when a finalized report exists, the report validates against its schema, every required Phase 1 and Phase 2 check has status passed, overall_status is pass, and staging-state validation during report finalization succeeds. The validation component shall not proceed to the promotion stage when any required Phase 1 or Phase 2 check has status failed, error, or skipped, or when report finalization (including staging-state validation) fails.
- `INIT-RVA-004`: The validation report shall not include a check that recursively validates the report itself. Fingerprint linkage, digest linkage, check ordering, check uniqueness, staging-state validation, report schema validation, and serialization are not ordinary profile checks; they are validation-component postconditions enforced during report finalization before promotion. Report finalization failure (including staging-state schema failure, fingerprint mismatch, digest mismatch, validation-status mismatch, linkage mismatch, ordering violation, report schema failure, or serialization error) shall be recorded as a pre-promotion failure and shall prevent promotion.
- `INIT-RVA-005`: Authority validation in Version 1 is limited to exact authority propagation: the initializer shall verify that authority.granted_by is present in the request, that the provenance record request_identifier equals the same value, and that the handoff manifest records the required linkage. The initializer shall not authenticate the governing issue, consult an external authority source, or validate authority values against an undefined execution-context source.
